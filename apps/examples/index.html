@ogdakke/fluidbox

A lightbox that feels like it’s made of something.

Images fly out of their thumbnails and land back where they came from. Pinch, wheel, and double-tap zoom, swipe between slides, drag down to dismiss. Use the custom elements, the headless runtime, or a framework binding — every demo on this page uses the same runtime.

  • ←→ or swipe to move
  • Pinch Wheel or double-tap to zoom
  • Esc or drag down to close

01 Custom elements

Plain markup, any aspect ratio

<app-gallery> collects every <app-lightbox> inside it. Portrait, square, and panorama images keep their shape in flight. The filmstrip is one more element.

Markup 
<script type="module">
  import "@ogdakke/fluidbox/elements";
  import "@ogdakke/fluidbox/styles.css";
</script>

<app-gallery aria-label="Landscapes">
  <app-lightbox item-id="dune">
    <button slot="trigger" type="button">
      <img src="/art/dune.svg" alt="Dune at golden hour" width="1800" height="1200" />
    </button>
    <template slot="content">
      <img src="/art/dune.svg" alt="Dune at golden hour" width="1800" height="1200" />
    </template>
    <span slot="caption">Dune at golden hour</span>
  </app-lightbox>
  <!-- …more items -->
  <app-filmstrip></app-filmstrip>
</app-gallery>

02 Indexed source

100,000 items, 12 thumbnails in the DOM

A LightboxSource describes the collection by index. The page renders only the cards it shows; an origin adapter tells the viewer where each one is. Jump anywhere and keep swiping.

Source and origins 
gallery.source = {
  count: 100_000,
  getItem: (index) => ({ id: String(index), media: { type: "image", src, width, height } }),
  getIndex: (id) => Number(id),
};
gallery.origins = {
  getOrigin: (id) => {
    const trigger = mountedCards.get(id);
    return trigger ? { trigger, visual: trigger.querySelector("img") } : null;
  },
};
gallery.open({ index: 49_999 });

03 Headless runtime

Bring your own controls

createLightbox() needs no custom elements. You own the thumbnails, and a portal renderer mounts whatever chrome you want — here a caption bar with a counter.

Controller 
import { arraySource, createLightbox } from "@ogdakke/fluidbox";

const viewer = createLightbox({
  source: arraySource(photos),
  origins: { getOrigin: (id) => ({ trigger, visual: trigger.querySelector("img") }) },
  portal: {
    mount({ target, controller, signal }) {
      const bar = renderCaptionBar(controller);
      const dispose = controller.subscribe((state) => bar.update(state));
      target.append(bar.element);
      return () => { dispose(); bar.element.remove(); };
    },
  },
});
thumbnail.addEventListener("click", () => viewer.open({ id }));

04 React

Any element can be the origin

@ogdakke/fluidbox/react composes the runtime from parts. The image can sit inside a richer card, a static preview can open a live iframe, and one trigger can stand in for a whole album.

Composition 
import { Lightbox } from "@ogdakke/fluidbox/react";

<Lightbox.Root items={photos}>
  <Lightbox.Trigger item={photos[0]} items={photos} asChild>
    {({ item }) => (
      <button type="button">
        <img src={item?.thumbnail?.src} alt="" data-lightbox-origin />
        <Lightbox.ThumbnailOverlay>+{photos.length - 1}</Lightbox.ThumbnailOverlay>
      </button>
    )}
  </Lightbox.Trigger>
  <Lightbox.Portal>
    <Lightbox.Previous /> <Lightbox.Next /> <Lightbox.Close />
    <Lightbox.Filmstrip />
  </Lightbox.Portal>
</Lightbox.Root>

05 Solid · Vue · Angular

Same gallery, three bindings

Each binding writes a source to an <app-gallery> and keeps it in sync. Switch the source and the next open uses the new collection.
